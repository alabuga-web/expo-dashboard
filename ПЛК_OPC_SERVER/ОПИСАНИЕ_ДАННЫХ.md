# Описание данных ПЛК / Factory I/O

Документ описывает: что за данные собирает проект, как устроены таблицы SQLite, что означает каждый тег и как интерпретировать значения.

Источник данных: **Siemens PLC (PLC_2)** + сценарий **Factory I/O** («Выставка демо»).  
Сбор: OPC UA (`opc.tcp://192.168.0.1:4840`), опрос ~1 раз/сек.  
Файл БД: `plc_data.db`.

---

## 1. Что это за данные

Это **телеметрия линии** (датчики, приводы, режим ПЛК), а не бизнес-KPI напрямую.

| Слой | Смысл |
|------|--------|
| **inputs** | Входы: датчики, фактическое положение механизмов |
| **outputs** | Выходы: команды на конвейеры, уставки, сброс |
| **memory** | Внутренние флаги ПЛК (часы, служебные биты) |
| **plc** | Состояние самого контроллера (RUN/STOP и т.п.) |

В `config_opc.yaml` теперь задан расширенный набор тегов под один экран производства: Vision/COLOR, сортировка, склад, конвейеры и манипулятор FX5.  
Файл `seed_demo_db.py` умеет заполнить `plc_data.db` реалистичной демо-историей этих тегов для replay без живой линии.

**Текущий демо-replay:** ~10 мин, шаг 1 сек, источник `opc`; старый снимок сохраняется в `plc_data.db.bak` при запуске `python3 seed_demo_db.py`.

## 2. Таблицы базы данных

В проекте две схемы. Файл `plc_data.db` сейчас соответствует **схеме CLI (слой 1)**.

### 2.1. Схема CLI — `plc_db.py` (текущий `plc_data.db`)

#### Таблица `readings` — история всех опросов

| Колонка | Тип | Описание |
|---------|-----|----------|
| `id` | INTEGER PK | Автоинкремент |
| `ts` | TEXT | Время UTC (ISO-8601), момент записи |
| `source` | TEXT | Источник опроса: `opc`, `s7`, `web` и т.п. |
| `tag_name` | TEXT | Короткое имя тега (ключ в приложении) |
| `tag_address` | TEXT | OPC NodeId, напр. `ns=3;s="Diffuse Sensor 1"` |
| `value_text` | TEXT | Значение в текстовом виде (см. сериализацию ниже) |
| `value_type` | TEXT | `bool` / `int` / `float` / `null` / … |

Индексы: `idx_readings_ts`, `idx_readings_tag (tag_name, ts)`.

**Сериализация значений:**

| Тип PLC | В БД `value_type` | В БД `value_text` |
|---------|-------------------|-------------------|
| BOOL | `bool` | `ON` / `OFF` |
| INT / DINT / enum | `int` | число строкой, напр. `8` |
| REAL | `float` | число (`repr`), напр. `9.999533653259277` |
| null | `null` | `null` |

---

### 2.2. Схема pipeline — `shared/db.py` (Docker / дашборд)

Создаётся при запуске backend (слой 2). Колонка сервера — `server_id` (не `source`).

#### `readings` — история

| Колонка | Описание |
|---------|----------|
| `id`, `ts`, `tag_name`, `tag_address`, `value_text`, `value_type` | Как выше |
| `server_id` | ID OPC-сервера из `config/servers.yaml` (`simulator`, `plc_2`) |

#### `tag_latest` — последнее значение каждого тега

| Колонка | Описание |
|---------|----------|
| `server_id` + `tag_name` | Составной PK |
| `tag_address`, `value_text`, `value_type` | Последнее значение |
| `tag_group` | Группа: `inputs` / `outputs` / `memory` / `plc` |
| `ts` | Время последнего обновления |

Используется для REST `/api/tags/latest` и WebSocket snapshot.

#### `server_status` — связь с OPC-сервером

| Колонка | Описание |
|---------|----------|
| `server_id` | PK |
| `endpoint` | URL OPC UA |
| `status` | `online` / `offline` |
| `last_error` | Текст ошибки или NULL |
| `updated_at` | Время обновления статуса |

## 3. Каталог тегов (записанных в `plc_data.db`)

### 3.0. Production-теги для нового экрана

| Группа | Теги | Как интерпретировать |
|--------|------|----------------------|
| Цвет / изделие | `vision_sensor_1_value`, `vision_sensor_2_value`, `fx3_vision_sensor_3_value`, `fx3_vision_sensor_4_value`, `color` | `0` = ничего; `1–3` = синее; `4–6` = зелёное; `7–9` = серое / metal |
| Выпуск | фронт `vision_sensor_1_value`: `0 → код` | +1 произведённая/распознанная деталь соответствующего цвета |
| Склад | `pop_up_wheel_sorter_1_left`, `pop_up_wheel_sorter_1_right`, `fx3_pivot_arm_sorter_4_belt` | фронт `OFF → ON` добавляет деталь в ячейку склада: left=синие, right=зелёные, FX3 sorter 4=серые |
| Рука FX5 | `fx5_pick_place_x/y/z_position`, `fx5_pick_place_x/y/z_setpoint` | факт и цель по осям X/Y/Z; ошибка позиции = расстояние между ними |
| Захват FX5 | `fx5_pick_place_grab`, `fx5_box_detected` | захват закрыт / коробка обнаружена |
| Поток | `emitter_1_emit`, `belt_conveyor_*`, `diffuse_sensor_*`, `fx3_*`, `fx5_*` | лампы активности этапов линии |

Коды Vision Sensor соответствуют Factory I/O в режиме **All Numerical**:

| Value | Цвет | Тип |
|------:|------|-----|
| 1 | синий | сырьё |
| 2 | синий | крышка |
| 3 | синий | основание |
| 4 | зелёный | сырьё |
| 5 | зелёный | крышка |
| 6 | зелёный | основание |
| 7 | серый / metal | сырьё |
| 8 | серый / metal | крышка |
| 9 | серый / metal | основание |

На фронте `/production` показываются: выпуск по цветам, скорость за 60 секунд, склад по трём ячейкам, процесс линии и движение манипулятора FX5.

### 3.1. Сводная таблица

| `tag_name` | OPC DisplayName | Группа | Тип | Направление | Что означает |
|------------|-----------------|--------|-----|-------------|--------------|
| `plc_operating_mode` | OperatingMode | plc | int (enum) | статус ПЛК | Режим работы контроллера Siemens |
| `diffuse_sensor_1` | Diffuse Sensor 1 | inputs | bool | вход | Оптический датчик наличия объекта |
| `fx5_dis1` | FX5 DIS1 | inputs | bool | вход | Дискретный датчик зоны FX5 |
| `belt_conveyor_1` | Belt Conveyor (2m) 1 | outputs | bool | выход | Команда «конвейер 2 м включён» |
| `factory_io_reset` | FACTORY I/O (Reset) | outputs | bool | выход | Сброс сцены Factory I/O |
| `clock_0_5hz` | Clock_0.5Hz | memory | bool | память | Внутренние часы ПЛК 0.5 Гц |
| `fx5_pick_place_x_position` | FX5 Pick & Place 1 X Position (V) | inputs | float | вход | Фактическая позиция X манипулятора |
| `fx5_pick_place_x_setpoint` | FX5 Pick & Place 1 X Set Point (V) | outputs | float | выход | Уставка позиции X |

---

### 3.2. Подробно по каждому тегу

#### `plc_operating_mode`

- **OPC NodeId:** `ns=3;s=OperatingMode`
- **Тип:** `SimaticOperatingState` (целое)
- **Смысл:** текущее состояние CPU ПЛК.
- **Интерпретация (из NodeSet):**

| Значение | Имя | Интерпретация |
|----------|-----|---------------|
| 0 | NotSupported | Не поддерживается |
| 1 | StopFwUpdate | STOP, обновление ПО |
| 3 | StopSelfInitialization | STOP, самоинициализация |
| 4 | Stop | STOP |
| 6 | Startup | Запуск |
| **8** | **Run** | **Рабочий режим (норма)** |
| 9 | RunRedundant | RUN в резерве |
| 10 | Halt | Останов |
| 13 | Defective | Неисправность |
| 15 | NoPower | Нет питания |

В снимке БД всегда **`8` (Run)** — ПЛК был в нормальной работе.

---

#### `diffuse_sensor_1`

- **OPC NodeId:** `ns=3;s="Diffuse Sensor 1"`
- **Тип:** BOOL → `ON` / `OFF`
- **Смысл:** диффузный (отражательный) датчик Factory I/O — есть ли объект в зоне считывания.
- **Интерпретация:**
  - `ON` — объект обнаружен
  - `OFF` — зоны пусты / объект не в поле зрения
- **В снимке:** всегда `OFF` — за ~10 мин объект перед этим датчиком не фиксировался.

---

#### `fx5_dis1`

- **OPC NodeId:** `ns=3;s="FX5 DIS1"`
- **Тип:** BOOL
- **Смысл:** дискретный вход зоны **FX5** (участок Pick & Place / связанные конвейеры). Обычно «деталь на позиции» / концевик / фотодатчик.
- **Интерпретация:**
  - `ON` — условие сработало (деталь на месте / датчик активен)
  - `OFF` — нет срабатывания
- **В снимке:** `ON` ≈ 84%, `OFF` ≈ 16% — зона живая, состояние менялось.

---

#### `belt_conveyor_1`

- **OPC NodeId:** `ns=3;s="Belt Conveyor (2m) 1"`
- **Тип:** BOOL (выход)
- **Смысл:** команда ПЛК на ленточный конвейер длиной 2 м №1.
- **Интерпретация:**
  - `ON` — конвейер должен работать
  - `OFF` — остановлен
- **В снимке:** всегда `ON` — линия гнала ленту непрерывно.

---

#### `factory_io_reset`

- **OPC NodeId:** `ns=3;s="FACTORY I/O (Reset)"`
- **Тип:** BOOL (выход)
- **Смысл:** служебная команда сброса сцены / состояния в Factory I/O (кубы, позиции, сценарий).
- **Интерпретация:**
  - `ON` (обычно импульс) — выполняется сброс
  - `OFF` — сброс не активен (норма в работе)
- **В снимке:** всегда `OFF` — сброс не дергали.

---

#### `clock_0_5hz`

- **OPC NodeId:** `ns=3;s="Clock_0.5Hz"`
- **Тип:** BOOL (memory)
- **Смысл:** системный генератор тактов ПЛК с частотой **0.5 Гц** (период 2 с: ~1 с ON + ~1 с OFF).
- **Интерпретация:**
  - Не технологический сигнал линии.
  - Полезен как **heartbeat**: если бит периодически переключается — цикл ПЛК жив и опрос OPC идёт.
  - Если «замёрз» — проблема связи, опроса или ПЛК.
- **В снимке:** ~50/50 ON/OFF — связь и цикл были здоровыми.

---

#### `fx5_pick_place_x_position`

- **OPC NodeId:** `ns=3;s="FX5 Pick & Place 1 X Position (V)"`
- **Тип:** REAL (float)
- **Смысл:** **фактическая** координата X манипулятора Pick & Place №1 (обратная связь). Суффикс `(V)` — аналоговый/вещественный канал.
- **Диапазон в снимке:** `0.0` … `10.0` (среднее ≈ 3.26)
- **Интерпретация:**
  - Близко к `0` — у «домашней» / нулевой позиции по X
  - Близко к `10` — у противоположной точки хода
  - Промежуточные значения — движение между точками
  - Сравнивать с `fx5_pick_place_x_setpoint`:  
    `|position − setpoint| ≈ 0` → приехал; большая разница → едет / ошибка позиционирования

---

#### `fx5_pick_place_x_setpoint`

- **OPC NodeId:** `ns=3;s="FX5 Pick & Place 1 X Set Point (V)"`
- **Тип:** REAL (float), выход
- **Смысл:** **целевая** позиция X, которую задаёт программа ПЛК манипулятору.
- **Значения в снимке:** в основном `0.0`, `2.0`, `10.0` — дискретные точки траектории.
- **Интерпретация:**
  - Смена уставки → команда «ехать в новую точку»
  - Стабильная уставка + `position` догоняет её → нормальный цикл Pick & Place

## 4. Как читать снимок в целом

По данным `plc_data.db` за эти ~10 минут типичная картина:

| Наблюдение | Вывод |
|------------|--------|
| `plc_operating_mode = 8` | ПЛК в RUN |
| `clock_0_5hz` мигает | Опрос и цикл ПЛК живы |
| `belt_conveyor_1 = ON` | Конвейер №1 включён |
| `factory_io_reset = OFF` | Сцена не сбрасывалась |
| `diffuse_sensor_1 = OFF` | На этом датчике объектов не было |
| `fx5_dis1` переключается | На участке FX5 есть активность |
| X setpoint ∈ {0, 2, 10}, position догоняет | Манипулятор отрабатывает точки по оси X |

Это **сырые сигналы автоматики**, а не готовые KPI (OEE, брак, throughput). KPI на дашборде expo обычно **считаются** из таких тегов или из сценария/симуляции поверх них.

## 5. Примеры запросов

```sql
-- Последнее значение каждого тега
SELECT tag_name, value_text, value_type, ts
FROM readings
WHERE id IN (SELECT MAX(id) FROM readings GROUP BY tag_name);

-- История позиции манипулятора
SELECT ts, value_text
FROM readings
WHERE tag_name = 'fx5_pick_place_x_position'
ORDER BY id;

-- Ошибка позиционирования (разница setpoint vs position по ближайшим ts)
-- удобнее считать во внешнем скрипте, сгруппировав по ts
SELECT ts, tag_name, value_text
FROM readings
WHERE tag_name IN (
  'fx5_pick_place_x_position',
  'fx5_pick_place_x_setpoint'
)
ORDER BY ts, tag_name;
```

Через API (схема слоя 2, при запущенном backend):

- `GET /api/tags/latest` — актуальные значения  
- `GET /api/history?server_id=plc_2&tag=belt_conveyor_1&limit=100` — история  
- `GET /api/servers` — online/offline OPC
